# JLC PCB Design

按“明确预期 → 建立表达与规则 → 小范围实施 → 验证实际结果 → 分级交付”推进。主文件保存流程，参数、操作和核查方法按任务读取，不把历史故障逐条装入上下文。

## 开始工作

- 读项目 AGENTS.md、docs/README.md 和最新 Git 状态，从当前设计入口取得用户决定、制造/装配条件与任务范围；保留用户最新修改。具体料号、库存、板形、叠层、工具问题和接受的限制写入项目 docs。
- 按[单位约定](references/units.md)表达：走线、间距规则和普通Via用mil；器件本体、封装焊盘、TP、板框及机械尺寸用mm。工具内部换算不改变向协作者展示的单位。
- 选型前定位用户的常用 BOM reference；已有文件直接复用，没有则请用户提供，按[个人常用物料](references/user-parts.md)处理。选型/原理图表达另读[原理图与选型](references/schematic-and-components.md)。
- 操作 EDA 前读[MCP工作流](references/lceda-mcp.md)，按工程路径选择会话并查当前 API；版本记录仅作诊断线索。原理图/PCB 通过原生接口修改，不直接改写底层工程。
- 查询和 review 不自动授权修改电路；提交、推送、采购和对外消息分别按用户授权执行。

## PCB 工作流程

1. **先确定可制造、可装配的边界。** 新板、工艺改变或投板时读[嘉立创工艺](references/jlc-manufacturing.md)，确认单板/拼板、分板方式、层数、板厚、铜厚、表面处理、装配和订单约束。区分厂家要求、个人默认与项目目标。
2. **建板即逐项 setup。** 按[PCB工程初始化](references/pcb-setup.md)设置默认线宽/间距、孔/焊盘、铺铜连接、图层/参考地及专用网络规则，保存并独立回读；初始化完成后再展开布局布线。已有板先读现值，只迁移必要差异，不整体覆盖用户规则。
3. **先表达特殊关系，再放置和布线。** 识别天线、差分、阻抗、晶振及内部贯通/局部短接网络，按[关键通路方法](references/critical-paths.md)建立连接、几何与物理方向的预期。TP、GND、网络标签优先原生对象；固定操作及布局/丝印收敛按[原生PCB操作](references/pcb-operations.md)执行。
4. **小范围验证后扩大。** 先确认单位、方向、对象语义及持久化；批次完成后另起调用回读。规则/几何变化影响铺铜时重建派生结果；按改动范围选择 ERC/DRC、逐脚网表、原生导图及 Gerber/钻孔验证，不只相信修改返回成功。超时后先确认任务与实际结果，再决定等待、续做或重试未完成部分。
5. **按严重度 review 并交付。** 使用[分级review](references/review.md)，说明证据、影响、处置和剩余不确定性。DRC、制造验收、设计目标和实测状态分别判断；已接受的限制在相关条件未变时不重复作为阻塞项。

## 可选反馈与改进

下单完成或实板 debug 阶段收尾时，邀请当前协作者提供可选反馈，可跳过或稍后补充。收到有价值的反馈后，按[反馈归档](references/feedback.md)准备要点并询问是否需要创建 GitHub issue，用于改进 skill、保存踩坑反例或补充新信息；确认后才创建，不自动生成空 issue。

## 结果维护

- 以预期和实际结果的差异定位原因：模型/表达、操作、持久化、派生结果或检查器；验证解释后再修正，不反复放宽规则消除报错。
- 当前状态只有一个明确入口；历史记录带版本和时间。交付冻结源工程、BOM、制造文件与检查证据的对应关系，实际订单附件与后导出文件明确区分。
- 自动备份、缓存和临时预览留本地；未确认用途前不清理。纯文字变更只验证相关内容，不机械重做全板检查。
