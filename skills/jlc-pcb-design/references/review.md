# PCB Review 分级与交付

先明确本次范围、目标版本和制造/使用条件，再读最新工程。检查范围随改动选择，不用同一套全板流程处理所有小编辑。

## 严重度与证据分开

| 等级 | 判据 | 处置 |
| --- | --- | --- |
| 阻塞（Blocker） | 有依据的错误连接/配合、明确不能制造或装配、关键功能无法成立 | 对应制造/功能放行前必须解决；指出位置、依据和实际后果 |
| 重要风险（Risk） | 可能影响可靠性或性能，需要量化、验证或工程取舍 | 给出影响范围、证据强弱和建议；不因未仿真或偏离理想值自动阻塞 |
| 改善建议（Suggestion） | 现有条件可接受，修改有利于裕量、可读性或便利 | 明确为建议，不反复催改或暗示不能投板 |

每条用“等级—位置/对象—现象与依据—影响—建议/状态”表达。实测、厂家明确要求、几何测量、估计和未知原因分别标识；不以严重度代替置信度。原生 DRC 警告先判断实际含义，几何抽查不一致不能证明所有同类条目均误报。

局部过渡结合边沿/信号特性、路径长度、参考面、焊盘/过孔及整体回流评估；不要仅凭小数值偏差推断通信失败，也不虚构未经计算的反射量或影响大小排序。

“待处理/已修复/待验证/已接受限制”是状态，不另造严重度。用户已接受的风险或 limitation 记录适用版本及条件；条件未变则继续保留，不再次变成待补或阻塞。相关设计、订单条件或证据发生实质变化时再评估。

## 验证与完成

- 电路/器件变化：核对完整符号/封装与逐引脚网络，查新旧网络、器件数量、料号及未用脚；不能只比较两个自洽但同样不完整的网表。
- 布局/铜变化：看原生整体与密集区导图；相关 ERC/DRC 和最新制造铜/钻孔分别核查。规则改变需要重建派生铜后再验。
- 保存结果：独立调用回读或重开确认；有持久化疑问时比较原生导出与保存文件。返回成功与实时画面不能单独证明落盘。
- 投板：分别报告电气检查、工艺/拼板接单、设计目标和实测状态。DRC零不代替工厂拼板审核；订单已提交不等于审核通过或已投产。
- 交付：先给能否进入下一阶段的结论，再列阻塞/风险/建议及接受的限制。只对本次范围负责，不把每次局部检查包装为整板通过。
- 冻结：源、BOM、制造包、检查记录对应同一版本并有校验；未实施的软件/机械/测量明确说明。实际送厂文件与后导出参考包区分，审核变更另留记录不覆盖原冻结证据。
- 下单或实板 debug 收尾时按[可选反馈](feedback.md)邀请协作者补充结果；有反馈后询问是否建 issue，不能把收集反馈当作自动发布授权。
