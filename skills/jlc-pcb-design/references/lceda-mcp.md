# LCEDA MCP 工作流与版本经验

## 连接、会话和关闭

- 使用已注册的LCEDA MCP工具，先help，再doctor和session.list，按工程路径选择会话。不要复用旧session ID或把前台窗口当成目标工程。
- 尚未连接时，可按环境配置启动 `lceda-pro --mcp stdio`。这是启动命令，不是已经连接成功的证据；不要为每次调用重复启动进程。工具名称和安装路径按本机发现。
- 多个进程可能是同一编辑器的辅助进程，不据数量关闭或kill。用户要求退出时优先原生保存、会话正常关闭或服务stop；停止MCP不等于卸载配置，也不保证所有GUI窗口一并退出。
- 没有可用原生接口时说明具体限制；可继续只读分析和文档准备，不直接改写底层工程代替编辑器。

## 原生编辑核查

- 先查当前doc/API签名；尺寸、坐标、旋转及属性单位先用少量对象验证。修改后另起调用回读，避免旧快照和异步未完成造成假成功。
- 选择正确文档后再取图元ID；复制的板可能具有相同图元ID。保留用户修改，不用旧快照覆盖整个工程。
- 控制信号同时核查上电、复位和掉电状态；多部件器件核对所有子部件、EP/PGND和隐藏脚，不能用已放置子集的ERC代替完整性检查。
- 规则修改不自动改变已布线路或旧铺铜。保存后按网络核对绑定、实际铜形状及制造输出，DRC分组树要统计真实条目而非顶层组数。
- 只依据库完整料号和采购编号选择候选；库返回结果不证明实时库存或SMT基础库分类。精确搜索无结果时可用型号搜索后筛选，不猜UUID。

## 4.1.71版本经验：使用前重新验证

来源版本：LCEDA Pro 4.1.71，bridge 4.1.71.7a7261be；观察日期2026-10-13至15。以下只用于诊断，不作为新版本的固定实现。

- SDK物理叠层读取曾返回undefined；可通过只读getDocumentSource检查PREFERENCE与LAYER_PHYS。不以空值覆写，也不把修改文档层文字当成改了物理叠层。
- 原生源码记录格式为JSON头、`||`、JSON数据和末尾`|`。只读对比可忽略ticket等更新时间字段；工程修改仍用原生接口。
- 制造优化铺铜曾在Gerber G36区域外另画8mil描边。完整铜边比填充边外扩4mil；测距必须包括描边半宽，不直接套用该数值到其它配置。
- 网络Copper Safe Spacing可绑定命名安全间距规则。读取完整现值、仅替换目标字段再整体写回，避免漏掉其它网；矩阵按行列名称识别对象，不硬编码索引。
- Wire.modify后原标签可能消失；需要重新读网表。标签create即使返回null也可能已生成，先回读定位，避免重复创建。
- 非GND网络用原生网络标签，GND默认Ground-GND符号。已有连续线上不要叠加重复Name属性，隐藏文字不等于删除电气属性。
- 某些Attribute.delete曾为无操作，Text.modify空字符串也曾不能清空。先读当前API并核实结果，必要时通过原生删除/重建，而非循环重试或改底层文件。
- PCB getAll Via可能包含元件内置过孔；不能把插件孔/NPTH按Via尺寸批量修改。以真实Gerber/钻孔确认尺寸，不能把低精度回读写回降低设计值。
- 多页原理图getPngFile可能返回ZIP；先查MIME和文件签名再解包，逐页视觉核对。
- 系统可能生成无扩展名SQLite库或自动备份。先确认是否被Git跟踪、进程占用及是否含设计数据，再按用户授权清理；不要按随机文件名直接判定无用。
