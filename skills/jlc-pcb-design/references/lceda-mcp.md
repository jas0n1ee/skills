# 原生 MCP 使用方法

- 优先使用已连接的 EDA 原生能力，先读当前 help/API，以 doctor、session.list 按工程路径确认目标，不固定历史会话、UUID、坐标单位或枚举。
- 将MCP服务与工程会话分别管理：复用存活服务，缺少目标工程时先在现有服务中打开；不要因一次超时或没有看到窗口便另启服务。传输已关闭、工程会话失效和编辑器长任务分别诊断，不能用重复启动代替恢复判断。
- 编辑前读取当前工程及用户修改，先小范围验证表达方式和单位。通过原生接口修改；没有可用接口时说明限制，不直接改写底层设计文件。
- 显示参数与采购身份分离，见[原理图表达](schematic-and-components.md#原理图表达)；具体 API 实现按当前文档选择，不固化旧版本调用顺序。
- **超时/中断不等于操作失败。** 重试前先确认任务是否仍在执行、是否已完成或部分生效，再决定等待、续做还是重试未完成部分；避免重复启动长任务或重复修改。无法确认状态时先保全现状并说明不确定性，不盲目重发。
- 当前结果按任务预期独立核查，不能以调用返回值单独判断完成；检查范围见[review](review.md)。
- 同步、选择、对象生成等实现细节、字段映射及版本故障保存在项目 docs 工具记录。遇到具体问题时按需读取并重新验证，不在此维护过期绕行步骤或历史 API 故障清单。
- 未确认工程归属及保存状态前不关闭会话或杀进程；工程源及必要快照保留，临时文件按项目约定存放。
- 收尾时确认本任务创建的会话/任务是否仍需保留；仅在确认无共享用途且工作已保存后正常关闭不再需要的自建会话，不以进程数量清理用户或其它任务的工程。主进程、窗口及辅助进程不能按数量直接等同；异常启动与连接状态留在项目诊断记录，不固化为版本故障清单。
