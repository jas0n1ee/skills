# AI化零件 · Fusion MCP

通过 Fusion MCP 完成原生机械建模，交付可编辑源模型和经过核查的制造文件。本 skill 保存跨机器复用的方法；当前工作区及需求子目录的 `AGENTS.md` 保存项目工作约定。

## 接入当前需求

1. 读取当前工作区和目标需求的 `AGENTS.md`、最新需求与修订记录；沿用已经确认的材料、加工方、机器、文件位置和交付格式。不要为使用本 skill 重写项目约定。
2. 按工作区约定确定本次需求目录。参数、建模脚本、源模型、测量、工艺证据和交付结果归属该需求；通用 skill 目录不存放零件文件或会话数据。
3. 从当前机器解析工作区、用户目录、临时目录、应用位置和 MCP 地址。不得硬编码另一台机器的用户名、macOS 路径、Windows 盘符或旧会话 ID。工作区约定了临时目录时沿用；否则使用工作区外的本机临时目录。虚拟环境不能直接跨操作系统复用。
4. 汇总关键尺寸、坐标基准、单位、装配与制造要求，区分已确认、来源事实、设计建议和待测数据。优先从已有资料取得答案，只有会改变设计的缺项才询问。照片比例不能替代实测；暂估尺寸可以用于概念模型，但不能标为可投产。

## 先验证 MCP，再操作 Fusion

连接时读取 [Fusion MCP 连接与执行](references/fusion-mcp.md)。可用随附的 [只读探测脚本](scripts/probe_fusion_mcp.py) 完成握手并取得工具 schema；脚本仅依赖 Python 标准库。

- 优先使用可用的 Fusion MCP 工具；会话工具列表中没有 Fusion 时，探测 Fusion 自带的本机 HTTP MCP。不要仅凭 `API/AddIns` 为空或 HTTP GET 返回 405 判断 MCP 不可用。
- 每次建立连接都先 `initialize`、保留响应的 session、发送 `notifications/initialized`，再读取 `tools/list`。以本机返回的名称、说明和 schema 为准，不照搬旧脚本参数。
- 建模前只读检查 Fusion 版本、活动文档、产品类型、单位、组件/实体和已有设计状态。根据需求定位目标文档，不能把当前活动文档自动当作目标。
- 无 MCP 连接时继续资料和方案工作，定位进程、监听端口或应用状态后恢复连接。无法恢复时明确说明阻塞点；不得改用外部 CAD 内核生成模型，再把导入结果描述为 Fusion MCP 原生建模。用户明确授权其他建模方式时按新要求执行。

## 在 Fusion 中建立可修改的设计

- 用 Fusion MCP 创建/修改真实草图、特征、组件和实体；需要脚本时通过实际 schema 支持的执行工具运行 Fusion API。外部 Python 可做计算、图表、打包或独立导出验证，不替代已经约定的 Fusion 建模。
- 新模型默认保留参数化时间线；修改旧模型先了解其历史和设计类型，不为套用模板盲目转换。将需要调整的关键尺寸命名为参数，以草图约束和特征表达设计意图；不能把所有几何固定后声称已具备完整参数驱动能力。
- 对外默认毫米。Fusion API 的内部长度通常为厘米：使用带单位的表达式或单位管理器转换；数值坐标、距离、面积、体积分别核对，不能仅改显示单位。记录原点、轴向、装配位置与打印放置变换。
- 多零件按装配关系组织组件，区分参考件、生产件与打印附件。切除、布尔、圆角等操作明确目标实体；避免依赖易变的列表下标、未经确认的面/边序号或过期实体引用。
- 按可检查的阶段建模，完成后检查实体数量、包络、关键孔位/壁厚、特征健康和装配关系。修改已有文件先保留可恢复版本，不覆盖用户未保存的其他工作。
- 写操作超时或中断后，先只读确认实际执行到哪一步、是否已生成文档/特征/导出文件，再决定修复或续做。不得盲目重放整段建模脚本导致重复特征或误覆盖。

## 按制造流程验证

按需要读取 [制造与交付检查](references/manufacturing.md) 的相应部分。

- **CNC**：先确认工厂与渠道，再读取该渠道的工艺证据。未明确时先问“你是在哪个工厂加工？”，工厂未定可继续概念设计。不同供应商的底孔、牙深、倒角与材料限制不得互套。
- **3D 打印**：从零件几何决定朝向、配合、壁厚、支撑和排盘；从当前项目约定取得机器、喷嘴、耗材与预设。交付拓竹项目时更新模型关联和放置，验证实际切片结果。项目约定的 P2S/PLA Matte 等默认值不推广给其他项目。
- 设计/导出/切片授权不自动包含上传供应商、下单、付款或发送打印任务；这些动作按用户已有授权范围执行。

## 保存、重开和交付

1. 保存能继续编辑的 Fusion 原生模型；按需求另导出 STEP、3MF、STL 或二维图，文件名带需求名与版本。截图、示意图和网格不能替代原生源模型。
2. 重新打开或独立重新导入实际导出文件，核查单位、实体数量、关键尺寸与源模型一致性；多件还要核查组件位置、装配干涉和活动间隙。原生重开验证与 STEP/网格验证分别记录。
3. 图纸和三维模型使用同一版本、尺寸及孔型；标明概念图/需求确认图/加工图的实际用途。未建立或未导出的文件不能列作已交付。
4. 在需求目录保存复现脚本与精简验证记录：模型版本、关键参数、加工方/设备、适用工艺依据、检查方法、结果和未解决项。跨机器续做重新发现本机环境、建立 MCP 会话，依靠已保存的模型与记录恢复工作。
5. 最终给出源模型、制造文件的可点击路径和必要的装配说明；按项目约定复制交付文件到下载目录等位置。明确哪些只经过程序检查、哪些做过 GUI 预览、哪些由用户实物验证，不混报阶段。

## 维护边界

本 skill 的文本和通用脚本通过独立 skills Git 仓库同步，默认技能目录的安装入口指向该工作副本。工作区 `AGENTS.md`、供应商原始资料、测量、F3D/STEP/3MF 等项目文件遵循该工作区的同步与版本管理约定。更新通用操作方法时改 skill；更新某个需求或目录约定时改对应项目文件，不复制整套项目规则到 skill 中形成两份配置。
